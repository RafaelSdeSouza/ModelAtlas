# Reproducibility and manuscript checklist (research preview)

ModelAtlas v0.3.0 is **research software under development**. The current photo-z example is a synthetic scientific demonstrator, not a calibrated astronomical survey analysis. This repository is suitable for private development; **do not describe any numerical photo-z bounds as survey results**.

## From a clean checkout

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[examples,test]'
python -m pytest -q
python examples/solar_activity.py
python examples/photoz_identification.py
python examples/photoz_architecture.py
```

Run the last two photo-z commands in this order: the architecture example reads the codebook and matched *synthetic* catalogue generated by `photoz_identification.py`. All outputs go to the ignored `outputs/` directory. On a headless machine, set `MPLBACKEND=Agg`.

The sunspot observational data are bundled under `data/`; see README for attribution. The photo-z code generates synthetic photometric data with seeded NumPy random generators. There is no need to download private survey data to run the examples.

## Figure semantics

| Element | Physical/statistical meaning | Caveat |
|---|---|---|
| Input node | One observed feature dimension | Not a latent variable unless explicitly labelled |
| SOM neuron | Learned prototype vector of the fitted codebook | Not a galaxy, observation, nor a probability density |
| Thin feature-to-neuron connection | Corresponding codebook component | Not a causal edge, feature importance, or an independent fit parameter from another model |
| Prism color | Selected codebook component or cell-level scalar | Interpret via colorbar and units |
| Lattice adjacency | SOM topology specified at training | Not physical 2D/3D embedding of galaxy space |
| Prism extrusion | Graphical depth cue, unless explicitly configured for metric-driven relief | Not evidence for a third learned dimension |
| Identified interval | Compatibility under assumptions described in SCIENTIFIC_NOTES | Not a confidence or credible interval |

For a manuscript figure, record the input dataset identifier, code commit SHA, package version, exact plotting call, train/test or sample-selection design, random seeds, and the assumptions governing any reported bound. Vector output via Matplotlib `savefig(..., format='pdf' or 'svg')` is preferred.

## Before associating the software with a paper

1. Replace the toy photo-z selection mechanism with a reproducibly documented survey application, if empirically claimed. Handle support/footprint mismatch and failed/unattempted spectroscopy separately.
2. Check sensitivity restrictions against an external design, not the observed success sample alone. An assumed Wasserstein radius does not become empirically validated because simulated truth happens to lie inside its bounds.
3. Add finite-sample uncertainty / bootstrap or confidence-region procedures separately from the *population identified set* and validate coverage if reported.
4. Add unit/regression tests for figure quantities and independently validate any optimization used for sharp bounds.
5. Freeze numerical environment and datasets, obtain collaborator agreement on credits, license, release notes, and cite the exact tagged version. Once public, archive a versioned release with a persistent DOI (e.g., using Zenodo).

## Branching and release policy

For a paper that is not yet public, start with a **private GitHub repository** and version the source. Use an explicit release only once the scientific interpretation and credit are agreed. `CITATION.cff` currently contains draft metadata: update it to reflect all actual contributors and the correct eventual publication reference before public release. Repo creation and license choice are controlled by the owner.
